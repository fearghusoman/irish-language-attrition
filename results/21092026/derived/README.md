# Derived results — 21092026 (47 participants)

This folder contains **derived data** produced by the R pipeline in `analysis/` from the raw Gorilla exports in `results/21092026/` (`data_exp_279099-vall_questionnaires.xlsx` and `data_exp_279099-vall_tasks.xlsx`). It is generated by running `Rscript analysis/run_real_data.R` from the repo root — re-run that script to regenerate these files after any pipeline change or new data drop; don't hand-edit them.

## `participant_dataset.csv` — one row per participant (47 rows, 218 columns)

The "tertiary/descriptive" dataset from codebook Section F: everything about a single participant collapsed to one row, for a simple participant-level regression or for reporting descriptive stats. Columns fall into three groups:

1. **Raw questionnaire answers** — one column per question (e.g. `gender`, `region_residence`, `leaving_cert_year`), plus a `_quantised` numeric-coded sibling for scale/dropdown items. Mostly for reference/QA, not direct analysis inputs.
2. **Derived scores** — the variables that actually go into a model:
   - The 4 core predictors: `proficiency_score` (currently `NA` for everyone — see "Known limitations" below), `exposure_composite`, `integrative_motivation_composite`, `multilingualism_count`.
   - Descriptive-only composites: `attitude_composite`, `learning_experience_composite`, `classroom_anxiety_composite`, `parental_encouragement_composite`, `linguistic_identity_now_composite`, `instrumental_motivation_composite`, plus standalone items like `self_rated_attrition` (the DV comparison item) and `curriculum_cohort` (pre/post-1999).
3. **DV summaries** — `production_accuracy_pct`, `recognition_accuracy_pct`, `n_recalled_full` / `n_recognized_only` / `n_neither` — the participant's overall recall/recognition performance across all 60 words.

**Use it for:** quick descriptive stats (e.g. average exposure score, correlation between self-rated attrition and actual accuracy), the participant-level supplementary regression, or spotting outliers/data-quality issues before running the primary model.

## `trial_level_dataset.csv` — one row per participant x item (2,819 rows, 10 columns)

The dataset codebook Section F's **primary confirmatory model** needs: `participant_id`, `item_id`, `category` (concrete noun / abstract noun / verb / adjective), `word_length`, `freq_rank`, `retention_level` (0 = neither recalled nor recognized, 1 = recognized-only, 2 = fully recalled), plus each participant's 4 core predictors repeated across their rows.

**Use it for:** fitting the trial-level mixed-effects model, e.g.:

```r
clmm(as.factor(retention_level) ~ exposure_composite + integrative_motivation_composite +
       multilingualism_count + word_length + freq_rank + category +
       (1 | participant_id) + (1 | item_id),
     data = trial_data)
```

This model itself hasn't been fit yet — this file is the input it needs, with no further joining/reshaping required.

**Why two files instead of one:** the participant-level file answers "who is this person and how did they do overall"; the trial-level file answers "does this specific person-item pairing get retained" — which is what lets the model separate participant-level effects (proficiency, motivation) from item-level effects (e.g. "book" being an easier word than "colour") via the two random-effects terms.

Row count is 2,819, not 47 x 60 = 2,820, because one participant has only 59 Round-1 trials in the raw export (a genuine incomplete-session data point, not a pipeline bug).

## Known limitations affecting both files

- **`proficiency_score` is `NA` for all 47 participants** — no CAO-points-by-year lookup table exists yet in the repo. Once supplied (columns `leaving_cert_year`, `leaving_cert_paper`, `leaving_cert_grade`, `points`), pass it as `cao_lookup` to `build_participant_dataset()` and re-run.
- The short/long-word Levenshtein tolerance used in rescoring (`analysis/R/scoring.R`) is still an unconfirmed placeholder (≤4 characters = "short") — worth confirming against the actual scoring protocol before treating borderline cases as final.
- Rows flagged `NA` in `n_recall_flagged` / `n_recognition_flagged` (near-miss typed responses) need manual review before the counts/DVs derived from them are treated as final.
